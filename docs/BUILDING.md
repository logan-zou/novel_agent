# 构建、续跑与故障恢复

本文补充 [README](../README.md) 的运行细节。项目从源码仓库安装。

## 原文与断点

每个 `novel_id` 对应一份固定原文。构建对解析后的章号、标题和正文计算内容指纹；
续跑与已完成任务跳过前都要核对原文和已保存章节。章数、字数相同也不能替换原文。

旧进度没有指纹时，只有全部已存章节与当前原文一致才会补录指纹。
原文改变、章节缺失或无法安全确认时，命令会停止，原知识库保持原样。
恢复原文件后可再次运行；修订版原文请使用新的 `novel_id`。不要通过删除指纹绕过检查。

已完成批次可以跨进程续跑，当前失败批次内尚未提交的实体暂存不会跨进程恢复。
不要同时启动两个进程写入同一个知识库。

## 并发构建

先预览输入和输出目录，不调用模型、不创建构建日志：

```bash
./novel-agent build-many ./novels --dry-run
```

再以低并发、每本一个批次试跑；确认配置和用量后，可去掉批次上限：

```bash
./novel-agent build-many ./novels --workers 1 --max-batches 1
```

知识库标识符取文件名去掉扩展名。不同目录的同名文件会报错，同一文件重复传入会去重。
如果之前用自定义标识符构建过，请继续用单本 `build` 命令续跑，或把输入文件名改为该标识符。

`build_many.sh` 顶部可配置文件列表、并发数、窗口、批次上限和日志目录，相对路径以脚本目录为准。
公开默认只预览原创样例，1 路并发、每本 1 批、关闭调试日志；`bash build_many.sh --run` 才实际调用模型。
`--run --max-batches 0` 取消每本批次上限。可以编辑顶部输入列表，也可以直接使用上面的 CLI。

每次实际运行在 `knowledge_base/_build_logs/` 下新建日志目录，可用 `--log-dir` 改根目录。
终端显示每本当前章节、完成批次与总体成功/失败数量；百分比按完成批次数计算。
状态变化约 1 秒内显示，长批次默认每 30 秒提醒进度，可用 `--progress-interval` 调整。
单本失败不影响其他任务，最后有失败则退出码为 1。
`summary.json` 的 `succeeded` 表示本次运行成功，设置批次上限时不代表整本已完成。
Ctrl+C 会终止子进程，重新运行可从已保存的批次继续。

`--debug` 会把模型输出、工具参数和原文片段写入日志，分享日志前请删除私有内容。

## 用量口径

输入和输出 token 来自模型返回的 usage。缓存拆分是按相邻 Agent 请求的 prompt 长度估算的
可复用前缀，不代表服务商实际缓存命中，也不能用作账单依据。历史记录可能使用旧口径。
失败流没有返回的 usage 无法计入本地记录，真实费用以服务商记录为准。

## 模型与工具恢复细节

模型建连失败、流式读取超时、连接重置或响应体未传完就断开时，默认等待 2、4、8、16、30 秒重试同一次调用，最多共尝试 6 次。
建连和流式读取共用重试预算，关闭 SDK 内部重试以免次数叠加。HTTP 408、409、429 和 5xx 也按此预算重试；其他 HTTP 错误直接返回。
每次重试关闭旧连接并重新收集输出，未完成的工具参数不会执行；之前成功执行的工具不会因此重跑。
详细日志保留失败尝试已输出的片段和重试提示，最终返回结果只使用成功尝试的数据。
失败流未返回的 Token 用量无法统计，因此本地用量记录可能低于服务端实际计费量。
重试耗尽后保留原有批次失败和断点续跑行为；运行中的进程需重启后才会加载新逻辑。

重复工具调用保护只累计“参数相同、返回内容不变、且期间无实际写入进展”的调用。
返回内容变化会重置该调用的计数；实际实体内容更新会重置无进展计数。
重复写入相同内容不算进展，工具结果会立即提示模型转向其他事项或结束任务。
接近重复上限时还会给出一次明确提醒；模型收到提醒后继续无进展重复才会中止。
软迭代限制和总轮数上限仍保留。

`search_entities` 的 `limit` 是整次查询的候选总量，默认 30、最多 100。
`total_matches`、`returned_count` 和 `truncated` 说明整体返回范围；`keyword_matches` 列出每个词的总命中、
精确名称/别名、名称部分匹配、摘要匹配及已返回数量。计数按实体去重，名称和摘要的命中可交叉。
`uncovered_keywords` 表示精确候选尚未全部展示，或有候选但完全未展示；应只对这些词少量或单独补查。
`unmatched_keywords` 表示当前目录没有名称、别名或摘要命中，不等于原文中没有该对象。
构建先读取已找到的主体；重复成功搜索时会给出有界的读取路径和补查词建议，不算写入进展，也不重置循环保护。

小说构建中的工具参数错误（非法 JSON、缺少必填字段、字段类型无效）和最终知识校验失败，
各最多反馈给模型修复 5 次（初次失败后额外 5 次）。
JSON 格式与字段错误按模型轮次共用参数修复预算，同一轮多个失败项只计一次，整轮工具成功后重置；
参数修复不会被“连续 3 次工具错误”或相同调用保护提前中止，但总轮数上限仍然有效。
JSON 语法错误会附上错误位置、原参数长度、指纹及有界的出错片段；反馈引用当前失败的参数，
坏工具调用仍不会写入模型的工具历史，也不会自动补括号或执行。多项错误的摘录总量受限，重试预算不变。
写入前会一次列出全部缺失和无效字段，包括设定必填的 `domain`，避免逐项补字段耗尽重试。
批量调用已成功的实体继续保留，只需重试失败项；参数修复耗尽时未完成的批次仍不会提交。
每次反馈具体错误，成功后继续当前批次；修复仍受总轮数和循环保护约束，未通过校验的知识不会提交。
构建常规预算最多 60 轮，结束后另有 8 轮独立收尾；达到 40 轮软上限且最近 8 轮无写入进展时也会进入收尾。
收尾只允许更新已暂存实体，或补齐该模型轮次开始前已明确缺失的链接目标，避免修复时间被新抽取任务耗尽。
确有其他知识未抽取时，模型须用 `continue_batch` 列明 `remaining_tasks`，在已有实际写入进展的前提下，
最多获批一次 24 轮同章续跑，之后再留 8 轮收尾。上下文、暂存实体和错误计数均延续；这是当前运行内续跑，不是跨进程断点。
每次可重试的最终校验失败仍确保至少还剩 8 轮用于修复及重新提交，最多 5 次；包括所有窗口的总预算最高为 140 轮。
参数修复、最终校验修复及独立收尾期间不受软迭代上限提前打断；
普通工具执行错误仍保留连续错误和重复调用保护，部分成功中的实际写入会计为进展。
实体暂存前会检查非空摘要和完整链接路径（例如 `[[characters/人物名]]`），错误会立即反馈且不覆盖已有暂存内容。
路径合法但目标尚未创建的链接仍允许暂存，以支持同批次稍后创建的实体；最终提交前统一检查目标是否存在。
模型声明完成但知识校验失败后，每轮成功的修复工具调用都会重新校验；全部通过就结束修复并提交，
即使修复发生在最后一轮，也不必再花一轮生成结束语。正常抽取阶段不会仅因当前知识合法就提前结束。
这项收尾行为只用于知识构建，问答仍需生成并校验最终答案。批量工具部分失败时会明确报告失败，不触发自动收尾。
失败项会持续参与校验，直到对应实体成功重试；无法定位实体的参数错误会阻止自动收尾，要求模型再次明确结束。
修正已暂存正文中的少量错字或链接可用 `patch_entities` 提交精确替换，保留其余正文及元数据；
旧文本必须唯一匹配，多处相同文字应提供更完整的上下文。同一实体的任一替换失败时，该实体保持原样。
补丁的修改前后文本相同时，错误会回显实际 `old_text` / `new_text`，要求核对原文并修正实际参数，或删除无需改动项；
匹配失败则提示重读当前已暂存正文。错误反馈会明确该实体本次全部替换未应用，重试时需保留其余仍需执行的修改，
同批其他实体已成功的修改无需重提。原样重试仍受现有循环保护限制。

缺失链接可通过 `inspect_repairs` 查看问题编号和目标候选，再用 `repair_links` 选择编号，
由代码复制目录中的真实路径，并保留链接别名和锚点。候选只作推荐，不自动按相似度纠字；问题过期时需重新检查。
编号只在当前构建会话内有效，不改变知识库存储格式。
缺失目标在同批次创建后，旧问题可用精确对应原目标的实体编号核验为“链接已有效”，
只解除这一条历史链接失败，不重写实体；错误目标和来源版本过期仍拒绝。
`inspect_repairs.link_failures` 会列出历史失败的编号、精确目标和可核验状态；
来源已变化且不能核验时，须重读并完整重提来源实体。重复核验不重复计算修复进展。
本批新建实体可用 `manage_entities` 更名或撤销：更名原子更新本批精确引用，名称冲突拒绝覆盖；
撤销仍被引用的实体会报错。已有落盘实体不允许更名或撤销。
相同补丁连续两次失败后，程序会额外提供当前暂存正文及结构化修复选项，
读取和检查不算写入进展，重复计数和总预算保持原有限制。

`patch_entities` 默认只修改正文，可通过 `field="summary"` 单独修正摘要，保留正文、别名和来源章节。
`read_entities` 的请求可指定 `field="summary"` 读取准确摘要及完整文档版本，或用 `field="content"` 只读正文；
默认 `field="document"` 保留完整文档读取。`section` 用于正文小节；旧的 `section="summary"` 在没有同名小节时兼容读取摘要。
摘要补丁匹配失败会直接反馈当前摘要与版本，继续使用小补丁即可，无需为修摘要完整重写正文。
写入或提交前会拒绝已知模型协议控制标记，保留原暂存内容并提示按原文重生成；不会静默删除标记或改动普通标签文本。
替换目标可使用 `new_entity_id` 选择已根据原文核对的实体，由代码复制其准确名称；与 `new_text` 二选一。
失败补丁按字段和请求编号追踪，成功修改另一字段或无关内容不会解除尚未完成的请求。
如果旧文本本不存在、完整目标文本已唯一存在，可重读后根据 `inspect_repairs.patch_failures` 的提示，
使用 `confirm_patch_satisfied` 确认指定失败编号。确认会核验完整实体版本、至少 8 个非空白字符的共同上下文及所有替换条件，
拒绝过期、短词、删除、重复旧文本和歧义请求；确认不重写实体，只把实际解除的失败计为有限的修复进展。
实体版本变化后，应重读当前内容并重新提交同一替换请求，取得新失败编号后再确认；
新编号会替代同一请求的过期编号，其他字段和无关请求仍须分别处理。同一版本的同一确认不会重复计算进展。

模型可调用 `finish_batch` 明确声明本批抽取完成，程序会等待整轮工具全部执行并统一校验；
同轮有失败、非法参数或截断时拒绝完成请求，要求修复后再次声明。
常规 60 轮的第 53 轮前会提示剩余 8 轮和当前修复清单，优先完成已知剩余事项；
连续三次实际写入仍只提交单个实体时，工具反馈会提示合并剩余独立实体，每次最多 8 项。
进入独立收尾后，仍未抽取的知识须列明任务申请续跑；范围拒绝的写入持续阻止提交，直到该实体成功写入。
续跑会撤销先前的完成声明，完成后须重新声明；失败、截断或同轮同时声明完成与续跑时，两种请求均不接受。
当前结构合法不会自行触发完成，未声明完成而耗尽所有可用窗口仍失败，不提交不完整批次。
